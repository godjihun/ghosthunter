# 기능 명세서

`gosthunter`(귀신게임) — 비대칭 멀티플레이 공포/추리 게임

이 문서는 [ghost_game_scenario.md](ghost_game_scenario.md)의 게임 디자인을 **검증 가능한 기능 단위**로 옮긴 것이다.
"왜 그렇게 설계했는가"는 시나리오 문서, "어떻게 구현했는가"는 [technical_design.md](technical_design.md)를 본다.

**상태 표기**: ✅ 구현 완료 / 🟡 부분 구현 / ⬜ 미구현

---

## 1. 용어

| 용어 | 정의 |
|---|---|
| **본체** | 귀신의 실물. 탐지 판정의 대상이며, 조사 단계에는 고정된다 |
| **영혼** | 본체에서 분리되어 돌아다니는 귀신. 공포스킬은 이 상태에서만 쓴다 |
| **흡수** | 공포스킬 적중. **사망이 아니며** 현실화 게이지를 채우는 행위다 |
| **현실화 게이지** | 0~100%. 흡수 성공마다 오르고, 100%가 되면 사냥 단계로 넘어간다 |
| **현실화** | 귀신의 투명이 풀리고 사냥 단계로 들어가는 것 |
| **약점 도구** | 6종 중 무작위 3종. 이 도구로만 탐지가 성공한다 |
| **탐지** | 도구를 사용한 순간 사용자 화면 안에 귀신 본체가 있는지 판정하는 것 |

## 3. 상세 명세

### 3-1. 탐지 판정 (DT-03)

**입력**: 도구 사용 위치, 도구 종류
**처리**: 서버에서만 수행한다. 아래 **세 조건을 모두** 만족해야 성공이다.

| 조건 | 판정 |
|---|---|
| 시야 | 도구를 쓴 순간 **귀신 본체**가 사용자 화면 안(상하·좌우) + 사거리 이내 + 벽에 안 막힘 |
| 약점 | 사용한 도구가 약점 3종에 포함 |
| 무효화 | 도구 무효화 상태가 **아님** |

**출력**: 성공/실패를 **사용자 본인에게만** 전송.

**주의**
- **영혼 위치는 판정에 쓰지 않는다.** 영혼이 눈앞에 있어도 본체가 화면 밖이면 실패다.
- **3D 거리로 잰다.** 수평 거리로 하면 위층에서 쓴 도구가 아래층 귀신을 잡는다.
- **성공과 실패의 표시 시간이 같아야 한다.** 실패가 빨리 끝나면 연출 속도 자체가 단서가 되어 시나리오 3-2의 모호성이 깨진다.

### 3-2. 공포스킬 (GH-07)

**전제**: 조사 단계 + 영혼 상태 + 쿨타임 종료

| 조건 | 값 |
|---|---|
| 사거리 | 1.5m (밀착) |
| 대상 | 생존 퇴마사. **흡수 이력은 보지 않는다** |
| 차폐 | 벽·문이 사이에 있으면 **실패** |
| 쿨타임 | 기본 30초 |

**결과**: 현실화 게이지가 1회분 상승한다. 대상은 공포 연출을 보지만 **사망이 아니므로 조작·도구·헌납이 전부 유지된다.**

**차폐 검사가 핵심이다.** 영혼이 문을 통과할 수 있어도, 실제로 통과해서 같은 공간에 들어와야 흡수할 수 있다.

**같은 대상을 몇 번이든 다시 흡수할 수 있다.** 대상별 흡수 여부를 기억하지 않으므로 "이미 흡수된 사람"이라는 상태 자체가 없다. 제동 장치는 쿨타임뿐이다.

### 3-3. 현실화 게이지 (GH-09)

```
게이지 += 흡수 1회당 상승량      (기본 20%)
게이지 >= 100%          →  사냥 단계
조사 제한시간 종료       →  사냥 단계
탐지 성공 (1~2번째)      →  은신 단계로 복귀, 조사 시간 회복
탐지 성공 (3번째)        →  퇴마사 승리
```

| 규칙 | 내용 |
|---|---|
| 인원 무관 | 게이지는 퇴마사 수와 무관하다. 누가 죽어도 조건이 깨지지 않는다 |
| 반복 허용 | 같은 대상을 반복 흡수해도 똑같이 오른다 |
| 탐지 시 | **줄지 않는다.** 탐지의 대가는 강제 복귀와 재은신 시간이다 |
| 공개 범위 | **양 진영 모두**. 위치 정보를 담지 않으므로 공개해도 안전하다 |

**최소 현실화 시간 = 쿨타임 × (100 ÷ 1회 상승량).** 기본값이면 30초 × 5 = 2분이다. 이 두 값이 판의 성격을 결정하므로 항상 함께 조정한다.

사냥 진입 시:
- 귀신 렌더러 표시 (전 클라이언트)
- 이동속도 8 m/s
- 본체 고정 해제
- **영혼이 나가 있으면 그 자리에서 본체와 합친다** — 안 그러면 옛 본체 위치에 표식이 남고 탐지 좌표가 얼어붙는다

### 3-4. 탐지 페널티 (DT-05)

**발동**: 약점 도구로 귀신 **본체**가 탐지된 순간. 영혼이 나가 있든 아니든 발동한다.

**처리 순서**

| # | 처리 | 비고 |
|---|---|---|
| 1 | 영혼을 **본체 위치로 강제 복귀** | 영혼이 나가 있던 경우에만 의미가 있다 |
| 2 | **도구 무효화** 타이머 시작 | 기본 15초. 이 동안 모든 탐지가 무조건 실패 |
| 3 | **본체 고정 해제** (GP-03 예외) | 무효화가 끝날 때까지 본체가 걸어다닐 수 있다 |
| 4 | 귀신 본인에게만 알림 | 탐지당한 사실은 퇴마사에게 통지되지 않는다 |

**해제**: 무효화 타이머 종료 시 **본체를 다시 고정**한다. 단 조사 단계일 때만 — 사냥 단계에 들어갔다면 고정하지 않는다.

**이 페널티는 벌이자 기회다.** 위치가 들킨 대가로 영혼을 잃지만, **무효화 시간 동안 아무에게도 안 잡히는 상태로 새 은신처까지 걸어갈 수 있다.** 퇴마사 입장에서는 "찾았다"와 "놓쳤다"가 15초 안에 결정된다.

**게이지는 줄지 않는다** (§3-3). 대가는 게이지가 아니라 강제 복귀와 위치 노출이다.

⚠️ **본체 고정 해제를 빠뜨리면 페널티가 순수한 벌로만 남는다.** 재은신이라는 이름의 근거가 사라지고, 한 번 들킨 귀신은 그 자리에 못 박힌 채 계속 탐지당한다.

### 3-5. 제단 판정 (DT-07)

**조건**: 서로 다른 도구 **3종**이 모임

| 결과 | 처리 |
|---|---|
| 3종 모두 약점 | 퇴마사 승리 → 결과 화면 |
| 하나라도 약점 아님 | 생존 퇴마사 중 무작위 1명 사망 + **제단 유지(회수 가능)** + 게임 계속 |

### 3-6. 은닉 정보 규칙

이 게임의 재미 전부가 두 비밀에 걸려 있다. **어떤 경로로도 새면 안 된다.**

| 비밀 | 보호 방식 | 주의 |
|---|---|---|
| 약점 3종 | 귀신 클라이언트에만 전송 | 결과 화면 전까지 공개 금지 |
| 탐지 결과 | 사용자 본인에게만 전송 | 자동 팀 공유 금지 |
| 귀신 위치 | 퇴마사 화면에 렌더링하지 않음 | 조명·**음성**·UI로도 새면 안 됨 |

⚠️ **귀신 위치는 데이터 차단이 아니라 화면 은닉이다.** 사전과제 범위에서 내린 결정이며, 그래서 **소리·조명처럼 위치를 암시하는 요소를 새로 넣을 때마다 개별로 막아야 한다.**

**이미 이 함정을 두 번 밟았다:**
- 귀신 암시 조명(GH-13) — 전원에게 켜면 투명한 귀신을 따라다니는 빛무리가 보인다 → 소유자에게만
- **거리 기반 음성(VC-01)** — 귀신이 말하면 위치가 그대로 드러난다 → **귀신 마이크 차단(VC-02)**

현실화 게이지는 위치를 담지 않으므로 공개해도 안전하다.

### ⚠️ 음성 채팅이 스택에 미치는 영향

**음성은 원래 스택에서 뺐던 기능이다.** 채팅을 텍스트로만 하기로 하면서 Vivox를 제외했고, 그 근거가 technical_design.md 1번에 "유료 전환 지점이 하나 줄었고 WebGL 호환성을 확인할 필요도 없어졌다"로 남아 있다. 음성이 다시 들어오면 **그 두 가지를 다시 확인해야 한다.**

| 확인 항목 | 이유 |
|---|---|
| WebGL 지원 | 브라우저에서 마이크·오디오가 실제로 동작하는가 |
| 무료 한도 | 제출 요건 NF-02 — 심사자가 유료 라이선스 없이 실행해야 한다 |
| 심사 기간 가용성 | Relay와 마찬가지로 서비스가 살아 있어야 한다 |

**VC-05(관전 청취)가 가장 까다롭다.** 사망자의 음성 수신 위치를 자기 몸이 아니라 **관전 대상의 좌표**로 옮겨야 하는데, 이는 3D 음성의 리스너 위치를 직접 제어할 수 있는 솔루션이어야 가능하다. 솔루션을 고를 때 이 요구사항을 먼저 확인할 것.
